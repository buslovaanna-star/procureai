# ProcureAI — Аналіз закупівель

Streamlit-застосунок для автоматичного аналізу залишків, розрахунку потреби та
розподілу замовлення між двома постачальниками.

## Як запустити на streamlit.io (безкоштовно, без Python)

### Крок 1 — Створіть репозиторій на GitHub
1. Зайдіть на [github.com](https://github.com) → **New repository**
2. Назва: `procureai` (або будь-яка)
3. Public → **Create repository**

### Крок 2 — Завантажте файли
Завантажте ці п'ять файлів у репозиторій:
- `app.py`
- `supplier_allocation.py`
- `barcode_mapping.csv`
- `requirements.txt`
- `README.md`

Натисніть **Add file → Upload files** і перетягніть усі п'ять.

### Крок 3 — Підключіть до Streamlit Community Cloud
1. Зайдіть на [share.streamlit.io](https://share.streamlit.io)
2. Увійдіть через GitHub
3. **New app** → оберіть ваш репозиторій → `app.py`
4. **Deploy** → через 1-2 хвилини застосунок доступний за посиланням

### Крок 4 — Використання
1. Відкрийте посилання застосунку
2. Завантажте шаблон продажів і залишків
3. Завантажте окремі прайси постачальників 1 і 2
4. Налаштуйте правила вибору в боковій панелі
5. Завантажте Excel-звіт з двома окремими замовленнями

## Структура шаблону продажів

| Вкладка | Зміст |
|---|---|
| Продажі | SKU + пари колонок місяць_кількість / місяць_рентаб% |
| Наявність | SKU + дні на складі по місяцях (0–31) |
| Залишки | SKU + залишок (шт) + в дорозі (шт) |

## Структура прайсів постачальників

Постачальник 1 завантажується Excel-файлом. Для постачальника 2 можна вибрати
Excel або постійне посилання Google Sheets. Онлайн-прайс перечитується кожні
5 хвилин; у застосунку також є кнопка негайного оновлення.

Для Google Sheets встановіть доступ **Усі, хто має посилання → Читач**. Не
публікуйте права редактора. Застосунок перетворює звичайне посилання на
захищений CSV-канал і не потребує Google-пароля або API-ключа.

Порядок колонок довільний, назви розпізнаються українською, російською та
англійською.

| Поле | Обов'язкове | Приклади заголовків |
|---|---|---|
| SKU або штрихкод | так | `SKU`, `Артикул`, `Код товару`, `Штрихкод`, `EAN`, `UPC` |
| Ціна | так | `Ціна`, `Цена`, `Price`, `Cost` |
| Назва | ні | `Назва`, `Название`, `Name` |
| Наявність | ні | `Наявність`, `Наличие`, `In stock` |
| Доступна кількість | ні | `Залишок`, `Available qty`, `Qty` |
| Знижка | ні | `Знижка`, `Скидка`, `Discount` |
| Lead time | ні | `Lead time`, `Термін поставки`, `Дні доставки` |
| MOQ | ні | `MOQ`, `Мін замовлення`, `Minimum order qty` |

Старий формат каталогу iHerb також підтримується автоматично.

## Відповідність штрихкодів артикулам

Файл `barcode_mapping.csv` створений із таблиці `штрихкода.xls` і містить
22 631 відповідність. Для другого постачальника застосунок автоматично:

1. Читає код із колонки `Штрихкод`, `EAN`, `UPC`, `SKU` або `Артикул`.
2. Знаходить внутрішній артикул у `barcode_mapping.csv`, не втрачаючи
   початкові нулі штрихкоду.
3. Формує замовлення з двома колонками: внутрішній `Артикул` і
   `Код у постачальника`.
4. Не включає невідомий цифровий код у замовлення та показує його на аркуші
   `Контроль штрихкодів`.

Щоб оновити відповідності надалі, замініть `barcode_mapping.csv` файлом з
двома колонками `Артикул` і `Штрихкод`, збереженим у форматі CSV UTF-8.

## Правила розподілу

Основна стратегія за замовчуванням — `Спочатку ДСН, решта — iHerb`:

1. Потреба в замовленні розраховується за продажами й залишками незалежно від
   того, чи присутній товар у прайсі iHerb.
2. Якщо SKU є в доступному прайсі ДСН, застосунок віддає ДСН всю доступну
   кількість з урахуванням MOQ, ліміту, lead time та мінімальної маржі.
3. Увесь залишок автоматично включається в замовлення iHerb.
4. Якщо SKU відсутній у прайсі iHerb, він не вважається недоступним: артикул і
   кількість залишаються в замовленні, а ціна та сума позначаються як невідомі.

Додаткові стратегії порівняння постачальників також залишені в налаштуваннях.
Для кожного SKU вони:

1. Відкидає пропозиції без наявності, з недостатньою маржею, завеликим lead
   time або невиконаним MOQ.
2. Порівнює ціну з урахуванням доставки/мита.
3. Обирає найнижчу ціну, пріоритетного постачальника в межах допустимої
   різниці або збалансовану оцінку ціни та строку.
4. За потреби ділить кількість між постачальниками з урахуванням доступного
   залишку та ліміту замовлення.
5. Перевіряє мінімальну суму замовлення постачальника й переносить позиції до
   іншого постачальника, якщо мінімум не виконано.

Результат містить два аркуші замовлень, `Нерозподілені SKU` з поясненням
причини та `Контроль штрихкодів` для невідомих або дубльованих кодів.

## Параметри аналізу

| Параметр | За замовчуванням | Опис |
|---|---|---|
| Мінімальна маржа | 35% | Місяці нижче → виключаються |
| Lead time | 14 днів | Час доставки від замовлення |
| Safety stock | 30 днів | Страховий запас |
| Safety при знижці | 60 днів | Запас якщо знижка ≥ порогу |
| Мін. місяців | 6 | Мінімум чистих місяців для "постійного попиту" |
| Мін. продано | 12 шт | За весь період |
| avail_K α | 0.7 | Коефіцієнт впливу наявності |
| λ | 0.25 | Сила часового зважування |
